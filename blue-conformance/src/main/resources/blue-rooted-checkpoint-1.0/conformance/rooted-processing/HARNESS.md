# RCP draft.2 conformance adapter contract

## Scope and qualification

The original 66 abstract fixtures and their independent selector/graph oracles are preserved. `identity/` verifies new internal-envelope constructors. `model/operation_model.py` and its tests execute a finite ownership/cause model with explicitly illustrative gas units. None implements Blue's production evaluator, cyclic identity or receipt verifier.

There are still 34 production obligations. Nine now have literal source/step plans and a v2 outcome checker: RUN-001, 002, 003, 007, 014, 020, 021, 023 and 025. Their actual revised-runtime status is **NOT_RUN**. The other 25 remain recipe-level; the runner reports NOT_RUN for them and an overall INCOMPLETE result rather than allowing their earlier boolean/equality assertions to claim conformance. The first-iteration recipes remain under `baseline/iteration1/` for completing those adapters.

Do not deploy this test-plan language as a MyOS business API. Implement each primitive through the supported public SDK/API or an explicitly named test-only cache/suspension seam. The application code must not recognize fixture names.

## Literal sources and actions

`examples/iteration2/` contains literal Blue YAML derived from the preserved working examples. `plans/` lists exact start, append, process, epoch-capture, cache/eviction/wait, assertion and restart steps. A `$capture` or `$source` object is a **harness substitution**, not a Blue value sent to the runtime. Resolve it to the actual previously captured canonical content identity or literal source before invoking the public boundary. Never replace a saved historical selection with a latest state.

Each step has a stable `stepId`. Each run must retain a completed transcript record for every setup and variant step. A repeated five-successor step requires indices 0..4. Later prerequisites cannot be reported executed after failure. A step selecting a historical successor is not a batch `ManagedRevisionCause`: five iterations call the existing one-successor boundary five times, preserving separate gas/failure/commit results.

Every logical Timeline and actor comes from the source's actual bound channel. Exact entry timestamps and predecessors are built/verified by the selected SDK/provider. An append identifies the actual target lineage through captured IDs. Time 10/15/20 is logical evidence, not a sleep schedule. Eviction and suspension steps may change only physical availability, not recorded birth, identity, activation or eligibility.

The cycle-entrypoint fixture submits **the same exact request to A** in each realm, then asks the driver to advance through A or B. It does not confuse that with submitting different Operations to different documents. The diamond's noncommutative expected log is independently sorted from the real captured B/C DocumentIds using the base component ordering; the adapter does not supply the expected order.

## Independent artifact lock

The runner requires `--artifact`, its independently expected SHA-256, and a source lock with its own expected SHA-256. It reads the JAR and every nested dependency itself. The lock is generated by the actual candidate build, not filled from an adapter's result:

```json
{
  "artifactSha256": "<actual 64 hex digits>",
  "sourceCommits": {
    "language": "<actual full commit>",
    "bex": "<actual full commit>",
    "coordination": "<actual full commit>",
    "myos": "<actual full commit>"
  },
  "dependencies": {"BOOT-INF/lib/<actual jar>": "<actual sha256>"},
  "specificationSetSha256": "<hash of this package's manifests/specification-set.json>"
}
```

The JSON above shows field structure, not executable example hashes. Zero hashes/commits and adapter-selected artifact identities do not pass. The nested dependency inventory must match exactly, including the package's non-Blue dependencies. Additional genuine source projects may appear in the sourceCommits map.

## Protocol

The adapter receives one JSON request on stdin: the fixture, literal plan, all literal source text, independently pinned artifact/dependencies/source commits, exact specification-set hash, a fresh **operational** request nonce, a request hash, and a fresh evidence directory. The nonce must never enter a Blue cause or semantic identity.

It writes a small response on stdout:

```text
schema/status=EXECUTED
fixtureId, requestNonce, requestSha256, specificationSetSha256
artifactSha256, sourceCommits, dependencies
runs: {exact-variant-name: {path, sha256}, ...}
calibration: {path, sha256}       # RUN-020 only
```

Each referenced file is JSON under that evidence directory, hash-checked by the runner. No absolute/path-traversal reference is accepted. Each file repeats the provenance above and contains:

```text
transcript[]:
  kind: SDK_CALL | HTTP | HARNESS_CONTROL
  planStepId, repeatIndex when needed, completed
  request: exact submitted arguments/envelope
  response: exact returned result/evidence

output:
  status, causeKind, budget
  before, after                  # independently inspectable semantic state projections
  ownedWrites[]                  # normalized aliases tied to captured real IDs
  events[]                       # complete ordered records, with origin alias + ordinal
  semanticReceipts[]             # full relevant records, with verified owner alias
  sourceBefore, sourceAfter      # exact external-source records, not latest guessed views
  gas: {charges[], total, rejected}

restart:
  before, after                  # nonempty exact evidence snapshots
  beforeCommandCount, afterCommandCount
```

`before`/`after` projections preserve scalar kinds and fields, but resolve known fixture aliases consistently. Retain the unprojected exact documents, content links, receipts and requests in the transcript too. Do not compare operational timestamps as business state or use copied summary booleans in place of the recorded values. The adapter's extractor is reviewed trusted code; this runner is not cryptographic proof that an arbitrary dishonest process executed a JVM.

The checker independently enforces named complete variants, anchored successful/failed statuses, expected business values, owner sets, event counts, unchanged failed state/source records, ordered successor positions, receipt-prefix retention, live joining, exact restart and specified cross-run comparisons. Alias normalization must not erase member/occurrence distinctions or alter actual order.

## Gas evidence

Every admitted charge has exactly `sequence`, `label`, `quantity`, `weight`, `amount`. The rejected charge adds `remaining`. Sequences are contiguous; booleans are not integers; positive quantities and weights multiply exactly; the admitted sum equals total; the next rejected charge exceeds the actual remaining allowance.

The checker uses `tariff-weights.json`, independently derived from the preserved Contracts/BEX manifests. Unknown labels or changed weights reject. These checks do not prove that the runtime performed the right *number of operations*. Real work-count correctness still comes from the independent reference path and maintained component conformance.

RUN-020 first requires a reviewed **uncached materialized reference** execution of the same P input on the same artifact. Its successful total is G. Every cold/cached/evicted/source-committed variant runs separately at G-1, G and G+1. Below must fail at the exact next charge of the reference trace; at/above must succeed with total G and the concrete expected parent result. All three boundary families require complete nonempty traces, never two equally empty observations. The calibration record includes its exact transcript and reference implementation source identifier. There is no fabricated production “80/20” tariff: those numbers occur only in the explicitly finite illustrative model.

## Additional evidence for history and cycles

RUN-007 retains five complete application records, each with from/to, success, receipt and gas, and compares the old source-receipt prefix and source events. Its output includes the actual final live group. No source rewind or source event re-emission is allowed. An existing source representation may advance through the narrowly permitted finalization protocol; receipt-prefix preservation is not the false requirement that every current byte must remain identical.

RUN-023 supplies `identityEvidence`: full history-basis operands and their claimed hashes, owner descriptor, actual entry live edges, requested root DocumentId, delivery descriptor, and base invocation/companion identities. The checker derives the entry SCC independently and recomputes the draft.2 wrappers. The base Blue receipts remain verified by the real SDK. The later literal detach produces a full `phaseRecords.split` result with frozen entry context, initial owners A/B, next singleton partitions and preserved subject receipt. Merely returning `sameIdentity: true` is insufficient.

## Failure reporting

A missing adapter is NOT_RUN. A recipe without a complete oracle is NOT_RUN, not a passing expected-negative case. Missing variants, failed prerequisites or mismatched provenance are failures of that attempted fixture. An overall selection containing unexecuted recipe obligations is INCOMPLETE (exit 3); actual failures exit 1; all selected qualified fixtures passing exits 0. No result from this runner independently claims full RC readiness.


The evidence directory must be new. Do not overwrite an older run. Candidate runtime/profile conformance, complete MyOS acceptance and source/manifest reproduction remain separate final gates.
