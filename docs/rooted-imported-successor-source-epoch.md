## Maintained basis and exact fixture

`FullLifecycleAdmissionTest.managedRevisionEventAcceptsAuthenticatedSameEpochComponentRebind`
already requires an imported receipt event to preserve the retained source epoch
when its only change is active-reference finalization. The new tests retain that
ordinary no-carrier control and add a carrier to a corresponding valid input.

The fixture uses the same complete host-supplied numbered source receipt pattern
as that maintained test. It does **not** invent a representation result:

1. A has inactive `/child` pointing to B0. B's authoritative numbered state is B2
   and its active `/parent` points to A. B1 has no emitted events; B2 carries one
   exact `child` event occurrence.
2. An actual PROCESS imports B1. A remains pending at epoch 1. Finalization
   changes B's active reference while preserving B2. The test checks the exact
   B2 anchor, unchanged epoch, changed identity, and empty source events.
3. That actual original input, committing result, and selected transition
   receipt construct `ManagedRepresentationTransition`. No output epoch is
   relabeled and no completed proof is synthesized. The next snapshot preserves
   all returned documents, lifecycle flags, epochs, components and occurrences.
4. The B1→B2 cause is processed against that same snapshot with and without the
   authenticated successor. Both must deliver exactly the original numbered
   event to A and advance A. Only the carrier must retain the exact inactive
   anchor/target cursor. The future representation cause must not execute.
5. In the finalizer-only case, no work targets B and replacing only B's active
   `/parent` value explains its entire body difference. The proposed regression
   expects B to remain at epoch 2.

The separate source-mutation control installs an actual B handler for A's
emitted event. It changes B's `/revision` from 2 to 3. With either carrier shape,
that genuine local change must still advance B to epoch 3. Wrong-occurrence and
non-null-next carrier negatives use the genuine transition, then exercise the
existing carrier constructor checks. A one-gas carrier invocation must roll
back to the exact input closure.

Two further controls sharpen the boundary without changing production:

- An actual external B handler advances the selected B2 state to B3. The test
  preserves that entire PROCESS result, then imports the older B1→B2 receipt
  without a successor carrier. Its exact event still runs in A, and its only B
  body change is active-reference finalization, but B must advance 3→4. This
  deliberately rejects a broad `receiptReconciled` exemption for ordinary
  nonterminal imports. No snapshot epoch is relabeled to simulate B3.
- A successful carrier invocation supplies the measured gas G. At G−1 the
  receipt-reconciliation work and imported-event handler must actually run,
  then fail atomically. The control checks literal document/epoch rollback,
  restoration of the original pending epoch 1 and absent cursor, absence of
  committed receipts/events/checkpoints, and an identical failed retry gas
  trace. This supplements, rather than replaces, the one-gas admission failure.

This is a complete-snapshot Language component test under the existing rooted

It is not an SDK root-capture or durable-host authentication test. It does not

## Narrow correction and normative limits

The current Contracts specification §5.7.1 keeps source-local mutations and
unexplained finalizer changes strictly epoch-advancing, with a narrow exception
for historical-target reference reconciliation. Its literal wording does not
separately describe the existing imported-event-after-activation helper; the
maintained test supplies that implementation/conformance precedent.
§7.5a.1 explicitly retains ordinary numbered receipt reactions while a successor
carrier defers activation and representation traversal. Neither it nor the
rooted frozen interval permits suppressing a **genuine** numbered source change.
§7.5 and §7.5a's activation, ordered-prefix, and numbered-extension guards remain
necessary and are not candidates for weakening.

The private predicate now permits either completed activation (the old path),
or an already-reconciled **numbered** receipt whose actual `ManagedRevisionCause`
carries a successor representation. Receipt reconciliation alone is deliberately
insufficient: ordinary older numbered steps and nonterminal representation steps
do not gain this exception.

The exact imported-event identity, source/consumer distinction, import-depth,
local-change, and complete active-reference explanation checks are unchanged.
No timestamp-based filtering, later-head substitution, new historical range,
activation bypass, or unconditional same-epoch classification is introduced.
The original test file remained byte-for-byte unchanged from the red run for
the first causal green check. The two adjacent tests were added afterward and
passed with both complete test owners (62/62).

## Why the correction belongs in Language

Language selects the source epoch while constructing the complete committing
result and its bound transition receipts. Coordination or MyOS cannot renumber
that authenticated result after publication, discard a source receipt, or treat
the later terminal C8 step as if C9 did not exist. Weakening equal-epoch
activation would hide the symptom and also admit genuine later source changes.
Extending the old frozen interval or substituting a later source head would
change the selected cause. Skipping the imported receipt event would drop
required consumer reactions.

The private classification correction instead prevents the spurious numbered
revision at the work boundary that creates it. It does not alter event order,
the selected receipt or future tail, tariff constants, gas-charging code, or a
public API. Exact outputs and execution-derived gas for affected scenarios must
still be qualified; this document does not assert universal unchanged totals.
