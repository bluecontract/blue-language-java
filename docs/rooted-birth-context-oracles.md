# Literal birth and context-boundary acceptance

RUN026 preserves the original authored child identity, appends real old inputs at
logical clock BASE+15 and BASE+19, then submits an actual managed creation at
BASE+20 through the SDK. Its two variants process the observer first or the
creator first. A root-local child remains unpublished until the creator owns its
birth. The test checks exact birth history, occurrence, original input order,
cause and commit companion; no prebirth counter change; one initialization;
unchanged independently owned source history; and retained-store restart.

Host INITIALIZATION receipts intentionally have no `sourceEntry`. This is checked
explicitly. The birth's complete source order identifies its actual journal entry,
and the independently captured original cause and source-operation companion bind
the receipt to that entry. No receipt field is synthesized by the collector.

RUN030 executes six actual packaged validation boundaries: extra reverse parent,
missing forward child, wrong root, wrong history basis, expanded publication set
and immutable historical witness promoted to writable. Each case retains complete
before/after state and the actual exception boundary. The valid calculation and
publication-envelope controls must succeed. The history-basis mutation recomputes
self-consistent wrappers and executes the changed context before offering it to
the original host authority check. Constructor acceptance alone is not treated as
history authentication.

The witness case uses saved initialized A0, genuine A1/A2 receipts, and the first
actual retained B application. It does not replace A0 with current A2 or claim B's
remaining history is complete. The literal request uses the runner's ordinary
reference capture form; nested `blueId` wrapping is not Blue wire syntax.

Both literal obligations passed on the sealed development MyOS JAR with SHA-256
`526715082665b44f44f031d702f2c8fbde0390dab74c7cf6a9cfe94692d1b25e`.
Sixteen mutations of the actual observations were rejected. These are SDK/artifact
and independent-oracle results. Public application companions and final artifact
repetition remain part of the complete product/release gates.

Original recipes remain byte-for-byte in `provenance/recipe-inputs`. All prior
runtime fixtures, gas checks and forged-evidence checks remain enabled.
